Features

Not a mock.
A protocol-aware adversary.

Faults are rendered in the service's own wire protocol and parsed back cleanly by the SDK — so your client sees the same exception classes it'd see in production.

Real error shapes, every protocol

Errors rendered via botocore service models across all 436 modeled services — json, query, ec2, rest-xml, rest-json, smithy-rpc-v2-cbor. A fidelity harness round-trips every modeled error code through the SDK's own parser.

Error.Code round-trips for 90k+ modeled shapes

A rule DSL, not flags

Match on service, operation, region, resource, headers, or jmespath over the parsed body — JSON, form-encoded and XML. Cadence via probability, deterministic hashing, rate windows, sequences and TTLs.

body: "TableName == 'orders' && Item.tenant.S == 'vip'"

Latency you can shape

Uniform, gaussian, spike distributions — or throttle response bodies to KiB/s.

Connections that die

TCP resets, timeouts, mid-stream aborts, truncated and corrupted bodies.

TUI dashboard

microburst dashboard — live fault feed over SSE, rules table, sparkline.

Observable chaos

Fired log with filters, SSE live tail, Prometheus /metrics, OpenTelemetry spans. Every fault is auditable — chaos you can defend in a review.

Ships everywhere

PyPI package, GHCR image, docker-compose example, composite GitHub Action — uses: pingedbrain/microburst@v0.3.0 drops it into any workflow.

The DSL

Declare the storm.

Rules are YAML — hot-reloadable via the control API at runtime. What AWS sees is a faithful fault; what you see is a deterministic experiment.

▸ chaos.yml
# 10% of DynamoDB writes throttle
- service: dynamodb
  operation: PutItem
  probability: 0.1
  error:
    code: ProvisionedThroughputExceededException

# the vip tenant always feels pain — deterministically
- service: dynamodb
  body: "Item.tenant.S == 'vip'"
  deterministic: true
  probability: 0.4
  latency: { dist: gaussian, mean: 800, stddev: 200 }

# S3 reads: 200 OK, corrupt payload. the insidious one.
- service: s3
  operation: GetObject
  response: { corrupt_bytes: 16 }
